When building a deposit service in Go, you need to reconcile incoming payments with your internal user accounts. The Go package is optimized for high-throughput routing and is a good fit for background workers and stream processors.

## Basic integration

```go
package main

import (
    "fmt"
    addresskit "github.com/Boxkit-Labs/stellar-address-kit/packages/core-go/addresskit"
)

func handleIncomingPayment(dest string, memoType string, memoValue string) {
    result := addresskit.ExtractRouting(addresskit.RoutingInput{
        Address:  dest,
        MemoType: memoType,
        MemoValue: memoValue,
    })

    if result.DestinationError != "" {
        fmt.Printf("Rejecting payment: %s\n", result.DestinationError)
        return
    }

    // Check the database for a user with ID: result.RoutingId
    // Base G-address of the pooled account: result.Address
}
```

## Routing worker example

A common architecture is to stream payments for a pooled account and route them into user balances:

```go
func processPayment(op operations.Payment) {
    if addresskit.IsMuxed(op.To) {
        decoded, _ := addresskit.DecodeMuxedAddress(op.To)
        routeToUserBalance(decoded.ID, op.Amount, op.Asset.Code)
    }
}
```

## Best practices

1. Make the routing step idempotent so reconnects do not double-credit users.
2. Record the operation ID or transaction hash in your database.
3. Validate addresses before processing withdrawals.
